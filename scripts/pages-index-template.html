Krauken

Open-source fermentation chamber controller for a Raspberry Pi.

v{{VERSION}} Raspberry Pi OS Debian package

What this is

Krauken drives a fermentation chamber end to end: a control daemon and hardware supervisor, a web API, and a React frontend, all running as one service on a Raspberry Pi. It can control the chamber through either a BrewPi-compatible Arduino controller (the common DIY fermentation-chamber setup) or the Krauken project's own custom PCB, and it can read Tilt hydrometers over Bluetooth LE alongside either one.

Early days -- v{{VERSION}}. The Krauken PCB is an open-source hardware design, not a product -- when it's ready, the design files go public and you build or order your own; nobody is selling assembled boards. Until then, this software runs on BrewPi/Tilt hardware you already have.

Install

Three steps: trust the signing key, add the repository, then install normally.

1
Trust the signing key
Downloads Krauken's public signing key and converts it to the binary format apt expects (gpg --dearmor). This is what lets apt tell a genuine Krauken package apart from an impostor claiming the same name. 
curl -fsSL {{PAGES_URL}}/krauken-archive-keyring.asc \
  | sudo gpg --dearmor -o /usr/share/keyrings/krauken-archive-keyring.gpg
2
Add the repository
Registers this apt repository as a package source, and tells apt to trust it specifically using the key from step 1 -- not just any key on your system. Nothing installs yet. 
echo "deb [signed-by=/usr/share/keyrings/krauken-archive-keyring.gpg] {{PAGES_URL}} stable main" \
  | sudo tee /etc/apt/sources.list.d/krauken.list
3
Update and install
apt update re-reads every configured repository's package list, including the one you just added. apt install krauken then actually downloads and installs it -- see below for what happens during that step. 
sudo apt update && sudo apt install krauken

What happens during install

  • Target is Raspberry Pi OS (or any Debian-based distro) on a Pi -- armv6l, armhf, and arm64 are all supported.
  • The package ships as source, not a prebuilt binary: it creates a real Python virtualenv and installs into it natively on your Pi (using piwheels.org for prebuilt wheels of compiled dependencies). This needs network access and takes longer than a typical apt install.
  • If you're installing on genuine Krauken PCB hardware, the installer can also build the small tool that provisions its ID EEPROM for auto-discovery -- but since the hardware hasn't shipped yet, that question is currently dormant and always skipped; nobody pays for a compile step they don't need.
  • If brewpi.service is already running on the box, the installer asks before stopping/disabling it -- it never deletes BrewPi's own files.

After you install

Check it's running:

systemctl status krauken-api krauken-daemon

The web API listens on every interface (0.0.0.0:8080) by default, since the Pi it runs on is normally headless -- browse to http://<your-pi's-address>:8080 from any device on your LAN with no extra setup. To restrict a given install back down to loopback-only, set KRAUKEN_API_HOST=127.0.0.1 in /etc/krauken/krauken.conf and sudo systemctl restart krauken-api.
